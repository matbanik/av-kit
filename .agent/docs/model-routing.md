# Model & CLI Routing

Capability classes are resolved through the shared read-only registry at `P:/.agent` plus this project's `.agent/model-registry.local.yaml`. The compiled sibling JSON is generated by the shared resolver; never edit it by hand. The local overlay adds five classes and preserves the approved av-kit bindings. Global defaults do not select this project's models.

## The routed stack

| Role | Class | Scope |
|---|---|---|
| Coordinator | `avkit_coordinator` | Planning, architecture, synthesis, governance and correctness reasoning |
| Builder | `avkit_builder` | One bounded mechanical implementation task with explicit criteria |
| Verifier | `avkit_verifier` | Read-only evidence collection; cannot approve work |
| Router | `avkit_router` | Classification and inventory; not implementation or review |
| Independent reviewer | `avkit_independent_reviewer` | Adversarial review in a separate context, different vendor, no authorship of the work |

The overlay is add-only: no inherited global binding is overwritten and no class inherits an upstream fallback chain. No provider, model upgrade, or worker capability is introduced. Interactive Claude Code coordinator selection remains the existing human-selected main session; the catalog has no avkit_coordinator binding on claude-code-agents. Do not translate that refusal into a substitute.

## Independent-reviewer chain (self-review prohibition)

1. Resolve `avkit_independent_reviewer` on `codex-cli` with the actual author vendor and project root. Require separate context, no authorship and vendor diversity. Routine effort is medium; risk paths/contracts use high.
2. PROFILE B3 has no second machine reviewer configured. No Gemini, headless Claude or cheaper checklist class can substitute.
3. Stop for **Mat**, PROFILE B4's named human reviewer, when the configured reviewer is unavailable, unauthenticated, ineligible or rate-limited. Record the actual decision and exact target/revision. The implementor never writes its own approved verdict.

Egress prohibitions in PROFILE C/E take precedence: do not send data or prepare an external-provider submission when egress is forbidden. Review authorization is not commit/push authorization. Machine continuation never satisfies a human gate. The review ledger owns round counting (plan 3, execution 6), continuation grants and stop readouts; a new loop must not evade a stop.

## Resolver contract

Set `AGENT_MODEL_REGISTRY_HOME=P:/.agent` in the dispatch process. Preserve an explicit `AGENT_MODEL_REGISTRY` selection; an invalid explicit file is an error, never permission to fall back. Every caller supplies `--project P:/av-kit` or PowerShell `-Project P:/av-kit`, a supported harness, and actual author vendor for reviewer resolution. Check the nonzero exit before launching a provider. No silent model default, empty substitution or global sync.

```powershell
rtk proxy uv run python P:/.agent/tools/resolve_model.py resolve avkit_independent_reviewer --harness codex-cli --project P:/av-kit --author-vendor ACTUAL_AUTHOR_VENDOR --format json *> C:/Temp/av-kit/reviewer-resolution.txt; $code=$LASTEXITCODE; Get-Content C:/Temp/av-kit/reviewer-resolution.txt; exit $code
```

Replace ACTUAL_AUTHOR_VENDOR from the author identity before running. Do not infer vendor from an assumed default driver. Shared module API equivalent: `Resolve-AgentModel -Class avkit_independent_reviewer -Harness codex-cli -Project P:/av-kit -AuthorVendor ACTUAL_AUTHOR_VENDOR`; use a child pwsh script with terminating errors and the canonical all-stream receipt pattern. Resolution success proves configuration, not authentication, available quota, sandbox readiness or live worker smoke.

## Delegation & nesting rules

Resolve the active driver through harness-profiles.md and its scoped local override first. Cursor remains `fresh_worker: none` until both smoke receipts pass. Installed definitions do not activate workers. Claude Code retains its recorded working route and human plan-to-execution gate. Worker tool restrictions and the protected verification log remain authoritative.

Delegate mechanical tasks only when a worker is authorized. Keep correctness decisions on the coordinator, verdicts on the independent reviewer, and irreversible acts/human gates with the human. Do not promote a worker to coordinator or reviewer. Use separate worktrees for concurrent writers. Retain the documented nesting cap of five; prefer independent bounded tasks over deep nesting. See model-delegation.md and subagent-delegation/SKILL.md for dispatch and acceptance contracts.

## CLI Dispatch Decision Table

| Task | Route | Effort |
|---|---|---|
| Scriptable validation | Registered D6 command; no model | n/a |
| Routine small plan/execution review, no risk contract | `avkit_independent_reviewer` | medium |
| Risk path, cross-package, contract or significant prior finding | `avkit_independent_reviewer` | high |
| Governance/design/troubleshooting | `avkit_coordinator` | resolved harness effort |
| Mechanical work | `avkit_builder` if authorized | resolved harness effort |
| Evidence collection | `avkit_verifier` if authorized | resolved harness effort |
| Classification | `avkit_router` if authorized | low |

No alternate cheap reviewer is configured. Full routing census and resolver receipts are recorded in the adoption plan's routing-census.md and registry-readiness.md. Literal loader model IDs are restricted to the generated agent-definition field and registry bindings; dated historical observations retain provenance.
