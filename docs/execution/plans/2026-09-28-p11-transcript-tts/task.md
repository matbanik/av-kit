### Evidence-First & Sequencing Rules

- **Per-MEU order.** Role order is `orchestrator → coder → tester → reviewer dispatch`. Each MEU runs FIC → all tests written → assertion Red (unit, then Electron) → Green → targeted gate → handoff.
- **What `[x]` needs.** The deliverable exists, and the handoff or walkthrough carries the changed files, exact commands, exit codes, counts and receipt paths.
- **What `[B]` needs.** One of: a reproduced external error with command, nonzero exit and pasted diagnostic (for example, Electron unable to launch under xvfb); a missing dependency; or a human decision. It must link a follow-up. "Too complex" is never a blocker.
- **Amendments.** Only TA-1..TA-7, and only in their class. Anything else is a stop.
- **Order around the review.** H1-6 (Windows gate) precedes H1-7, so the reviewed code is the Windows-gated code. H1-6 is the one planned turn boundary: a human-run external step, not a politeness stop. H2 artifacts record the verdict and follow approval in the same pass. The dividers are ordering rules, not turn boundaries.
- **Recitation.** Re-read this table after each MEU handoff and at the start of H1.
- **Commits.** No commit or push without a direct human instruction.
