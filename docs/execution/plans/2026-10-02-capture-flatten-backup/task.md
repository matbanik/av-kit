### Evidence-First & Sequencing Rules

- Each cycle goes FIC → all tests → assertion Red → Green → targeted gate. Red assertions are never edited in Green. Only `TEST_AMENDMENTS` TA-1 to TA-9 change existing expectations, and only as written.
- `[x]` needs the deliverable plus durable evidence (the handoff or `walkthrough.md` carries `evidence.v1`). `[B]` needs a `### B-<row-id>` block and a linked follow-up.
- After every renderer edit that an Electron AC covers, run `npm --prefix ui run build` and then the named Electron `-g` spec.
- The committed audit baseline is written only by the authoritative Windows run and `baseline_carry.py`; it is never hand-edited.
- H2 artifacts are created only after review approval. The author never writes a verdict. Commit and push go to the designated branch only, and only on the user's direction; there is no merge, release or deploy.
