### Evidence-First & Sequencing Rules

- Each MEU goes FIC → all tests → assertion Red → Green → targeted gate → handoff. Red assertions are never edited in Green. `TEST_AMENDMENTS` holds exactly TA-1 to TA-14 (with TA-3a and TA-3b; TA-14 added at row 5 by D-95); no other existing expectation changes in this plan, and `ta-check` enforces it.
- A Red test imports any symbol the Green row creates **inside the test function**, so the module still collects. Only the symbols declared for that MEU in `validate-task.ps1` (`$PY_SYMBOLS`, `$TS_SYMBOLS`) may fail to import or call.
- Every AC test name carries its id: `ac_7x_n` in Python, `AC-7x.n` in TypeScript. The Red parsers count coverage per AC by that tag.
- GUI Red assertions fail on an `expect()`, never on a missing element lookup that throws first.
- After every renderer edit that an Electron AC covers, run `npm --prefix ui run build` and then the named Electron `-g` spec (reflection 2026-09-20 KEEP). `ELECTRON_RUN_AS_NODE` is cleared by the runner.
- `[x]` needs the deliverable plus durable evidence (the handoff or `walkthrough.md` carries `evidence.v1`). `[B]` needs a `### B-<row-id>` block and a linked follow-up.
- Decisions made during execution are appended to the plan's `decision_log` under the next free decision id, so the reflection's decision sources stay the plan and the grouping.
- H2 artifacts are created only after review approval. The author never writes a verdict. The agent never commits or pushes; there is no merge, release or deploy.
