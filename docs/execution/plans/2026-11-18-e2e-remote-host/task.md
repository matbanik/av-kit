# Task — Run the full E2E suite on the second Windows host through tracked tooling

> **Project:** `2026-11-18-e2e-remote-host`
> **Type:** E2E runner tooling with no MEU (triage D-1212, grouping D-1215): `CI-E2E-FLEET-HOST-UNTRACKED`, settled by D-1221 A (a Python command under `tools/` with Windows PowerShell 5.1 host scripts beside it), D-1222 A (an untracked local config), D-1223 A (check and name), D-1224 A (refuse when busy, stop nothing) and D-1225 A (a tracked known-failure list bound to open issues)
> **Estimate:** medium-large. One new tool (about 600 lines, standard library and PyYAML), seven host scripts (about 400 lines), one pytest file (about 700 lines, about 70 tests), one run book (about 150 lines), one `commands.md` row, one issue resolved and one grouping row. Runtime: the full `py-tests` suite; one real `check` (seconds) and one real `run` on the mini-air (about 15 minutes of host build and 20 minutes of suite; the tool's ceiling is 110 minutes from the task start). No product suite runs on the dev PC, and no product behaviour, API, OpenAPI, UI or Python package changes.
> **Working directory:** every command runs in `pwsh` from `P:/av-kit` on `main`. Session receipts go to `C:/Temp/av-kit/e2e-remote-host/erh-*`; the tool's own receipts go to `C:/Temp/av-kit/e2e-remote/<run-id>/`.
> **Execution gate:** `plan_to_exec_gate: human`. Mat's approval comes after the Codex plan review approves (his 2026-11-18 words, plan §Status); nothing here runs before that. No row commits or pushes without Mat's words. There is no human check row: the tests, the fixture runs on Windows PowerShell 5.1 and the real `check` and `run` prove the change.

- **Evidence-first completion:** a row is `[x]` only when its deliverable exists and the handoff/walkthrough carries the evidence bundle (AGENTS.md §Execution Contract).
- **The review barrier resolves the old reflection↔review cycle:** the handoffs (H1-6) are created *before* the review (they are the review's input); the reflection/metrics (H2) are created *after* `approved` so they can record the verdict. Do not create H2 artifacts during H1, and do not dispatch the review (H1-7) before the handoffs exist.
- **Self-review prohibition:** the implementing agent dispatches and collects the H1-7 review; it never authors the `approved` verdict itself (AGENTS.md §Execution Contract).
- **`[B]` is evidence-gated:** valid ONLY for (a) a reproduced *external* error, (b) a missing dependency/credential/permission, or (c) a human-decision gate — each with a linked follow-up and, for (a)/(b), a row-bound `### B-<row-id>` block with command, nonzero exit and pasted decisive error as `evidence.v1`; decisions need a durable decision link. The row cites `B-<row-id>` and `follow-up [label](target)`. Subjective reasons ("too complex", "no time", "out of scope", "later") are invalid; no error artifact ⇒ not blocked ⇒ keep working (AGENTS.md §Execution Contract).
- **Dispatching the H1-7 review is a blocking step, not a turn boundary:** continue to H2 in the same pass once the `approved` verdict file lands. The only sanctioned turn-enders are DONE, review cap, reviewer unavailable, or human decision; compaction continues (AGENTS.md §Execution Contract).
