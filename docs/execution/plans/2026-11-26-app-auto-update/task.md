# Task — the app checks GitHub Releases on a schedule, downloads a newer version and installs it on one click

> **Project:** `2026-11-26-app-auto-update`
> **Type:** distribution, main process, settings (core, API, UI, MCP) and E2E tooling. MEU-173: the feed block in the builder config, a feed check script and a publish checklist. MEU-174: one settings leaf in every layer, the `electron-updater` dependency, two main-process modules with three IPC channels, an Updates section in Settings, the installer macro (the cache line, the sign-in lines inside the update guard, a bounded running-app check), an install stage for the remote E2E tool, and a real update on the mini-air host.
> **Estimate:** large. 21 work rows; about 51 files (about 23 new); one new npm dependency with its lock file; three installer pack runs on the dev PC (rows 3 and 16, about 60 minutes together); two runs on the mini-air host (rows 7 and 17, about 90 minutes together). One OpenAPI regeneration. No version change, no upload.
> **Working directory:** every command runs in `pwsh` from `P:/av-kit` on `main`; the Vitest and npm commands of `ui/` use `Set-Location 'P:\av-kit\ui'` and return to `P:\av-kit`. Receipts go to `C:/Temp/av-kit/2026-11-26-app-auto-update/` with the prefix `aau-`.
> **Execution gate:** `plan_to_exec_gate: human`. The grouping's run parameters for this session are `commit_plan=false · exec_after_plan=false · commit_exec=false · push=never`, and the grouping's D-1413 is ruled (Mat, 2026-11-26, 'drafts stand'): no row starts until the plan review has approved, Mat has given the execution approval, and the coordinator has written both into the plan's Status line (S1). Rows 12 to 18 build the recommended option of D-1543 and D-1544, which are Mat's; they may run while the two are unruled, because nothing reaches a user before Mat's own release, and they stop if he rules differently (S2). No row commits, pushes, tags, uploads, creates a release or changes the version. There is no human check row: Vitest, pytest, the Electron E2E and the scripted update on the host prove the behaviour.

### Evidence-First & Sequencing Rules

Evidence records follow `.agent/docs/output-evidence-policy.md`; raw receipts are working
data. Each completed row points to durable pasted observations. The H1-3 and H1-4 commands
are this project's own. No placeholder command remains; the review cap is 6 unless the
ledger says otherwise. No stop hook is installed by this template.

- **Evidence-first completion:** a row is `[x]` only when its deliverable exists and the handoff carries the evidence bundle (AGENTS.md §Execution Contract).
- **The review barrier resolves the old reflection↔review cycle:** the handoffs (H1-6) are created *before* the review (they are the review's input); the reflection/metrics (H2) are created *after* `approved` so they can record the verdict. Do not create H2 artifacts during H1, and do not dispatch the review (H1-7) before the handoffs exist.
- **Self-review prohibition:** the implementing agent dispatches and collects the H1-7 review; it never authors the `approved` verdict itself (AGENTS.md §Execution Contract).
- **`[B]` is evidence-gated:** valid ONLY for (a) a reproduced *external* error, (b) a missing dependency/credential/permission, or (c) a human-decision gate — each with a linked follow-up and, for (a)/(b), a row-bound `### B-<row-id>` block with command, nonzero exit and pasted decisive error as `evidence.v1`; decisions need a durable decision link. The row cites `B-<row-id>` and `follow-up [label](target)`. Subjective reasons ("too complex", "no time", "out of scope", "later") are invalid; no error artifact ⇒ not blocked ⇒ keep working (AGENTS.md §Execution Contract). For this plan the one foreseen case is S9 (the host refuses the unsigned installer, or is unreachable): rows 7, 16 and 17.
- **Dispatching the H1-7 review is a blocking step, not a turn boundary:** continue to H2 in the same pass once the `approved` verdict file lands. The only sanctioned turn-enders are DONE, review cap, reviewer unavailable, or human decision; compaction continues (AGENTS.md §Execution Contract).
