Queue Cards

One card system for the Downloader and Convert queues — with Transcript and TTS converging onto the same primitives — replacing bare tables and the 13-button control bar with self-describing cards, state-dependent actions, and Gmail-style multi-select. GUI-only: every verb maps to an existing REST call.

What changesQueue tables become row-cards with inline progress, status pills, and per-card actions. Style and primitives come from Zorivest — both apps already share the same Dracula token base.
Why cardsA queue is a scanning task, not a column-comparison task. Research consensus: vertical row-cards with fixed internal zones beat both tables and free-form cards for job queues.
Control modelOne state-dependent primary action per card (empty slot when no verb applies) + kebab for the rest; checkbox multi-select with a contextual bulk bar; global toolbar shrinks from 13 buttons to 4.

  • Checkbox is a sibling of the clickable card body (stopPropagation) — clicking it never opens the item. Zorivest's exact pattern.
  • Status icon at the left edge — the fastest-scanning position — plus a text pill on the right. Never color alone (WCAG 1.4.1).
  • One primary action, state-dependent: Retry when failed/cancelled (existing per-id retry), Open when done, Cancel only on the in-flight row — wired to the existing queue-level cancel (POST /downloads/cancel / POST /conversions/cancel). There is no per-item cancel API and none is added. Pending rows show an empty slot; Remove stays in the kebab: Open file / Open folder / Copy URL / Move up · down · top · bottom / Remove.
  • Pause stays queue-level (per the 06-gui spec's state machine) — no per-card pause button to puzzle over.
  • Selection fill is an accent tint, not bg-bg-subtle — av-kit's --color-bg-subtle is #6272a4, identical to --color-neutral (a text color), so reusing it would paint selected cards comment-purple. Proposal §4 locks the remap.

03Multi-select & bulk actions — try it

Checkbox any card below (shift-click selects a range). The bulk bar appears only when something is selected — the Gmail / Carbon / Polaris contextual-bar pattern, using Zorivest's existing BulkActionBar component.

  • Header checkbox = select all (indeterminate when partial), operating on the filtered list.
  • Bulk bar is sticky above the list — matching Zorivest, so muscle memory transfers between the two apps.
  • Bulk execution is client-side fan-out only — N sequential calls against the existing per-id endpoints (retry, DELETE /{id}, PUT …/reorder). No POST …/bulk endpoint exists and none is invented.
  • Bulk results are itemized: 12 removed, 2 skipped (processing) — never a silent partial failure (G35).

04Global toolbar: 13 buttons → 4

Before — Convert page today (13 buttons, Start → Open folder)

✕ 13 choices, mixed sizes, per-item verbs mixed with queue verbs, destructive next to benign

After — proposed

✓ Queue-level verbs only. Per-item verbs moved onto the cards; move/retry/remove also in the bulk bar; Clear all… behind ⋮ with a verb-labeled confirm ("Remove 12 jobs")

  • "Clear finished" is a new control with no backing route — implemented as client-side fan-out of the existing DELETE /{id} over Done jobs only (output files stay on disk), with a G35 partial-result toast. No new REST endpoint.
  • Destructive ladder: queue-level cancel of a re-queueable job — no dialog; remove from queue — light confirm; clear all — full confirm. Overusing confirmation dialogs trains click-through (NN/g). Note: a shared ConfirmModal is new work — Convert's is a page-local portal, and Downloader's Clear All currently has no confirm at all.
  • Reorder: ships first as Move up/down/top/bottom (kebab + bulk bar + Alt+↑/↓), then drag handles via dnd-kit as a later enhancement — drag is never the only path (accessibility).
  • G31, correctly scoped: it bans per-page accent forks (e.g. inventing a green Save button color) — it does not collapse every control to variant="primary". The full G34 5×3 variant grid (primary / secondary / ghost / destructive) stays exactly as Convert already uses it; status colors appear only on pills, icons, and progress fills.

07Open decisions — need explicit locks before /create-plan

1 · Bulk bar placement. Recommended: sticky above the list (Zorivest parity). Alternative: floating bottom bar (Linear-style).
2 · Remove semantics. Recommended: light confirm now; switch to undo-toast once the API can restore a removed job (it cannot today).
3 · Drag-and-drop timing. Recommended: defer to M7 — keyboard/menu reorder ships first.
4 · Density toggle. Recommended: skip. One density, no zombie features.
5 · Per-card Cancel semantics. Recommended: per-card Cancel = the queue-level cancel, shown only on the in-flight row; other rows' primary slot stays empty, Remove in kebab. No new per-item cancel API this session (that would be a processor-state-machine change).
6 · Clear-finished semantics. Recommended: client fan-out of DELETE /{id} over Done jobs only, files stay on disk, G35 partial-result toast, no new REST. Alternative: also sweep Cancelled/Skipped — a product decision needing an explicit lock.
