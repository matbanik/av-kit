Capture page: one global row, one per-shot toolbar

Capture has three kinds of control that today sit in the same two rows: things that act on the app (capture a region, change the hotkey), things that act on the selected shot (save, delete, open, annotate), and settings (inbox folder). This mockup gives each its own home: a header row for capturing and settings, a toolbar above the viewport for everything that touches the selected shot, and a filmstrip that shows thumbnails instead of clipped names.

03Why these moves

  • Separate the three concerns by row. Global (capture, settings) at the top, per-shot in the viewport toolbar, next to the thing they act on. The two identically labelled Save buttons become “Save overlay” beside the drawing and “Save settings” inside the settings disclosure.
  • Settings are a disclosure because the inbox folder and hotkey change once. They also exist on the Settings page; the disclosure keeps them reachable without spending a permanent row.
  • The hotkey is shown where it is used. A key cap on the Capture button replaces a read-only input the user cannot type into anyway; the conflict banner then sits right under it.
  • Thumbnails, not truncated file names. Shots are visual; a 56×36 thumbnail distinguishes them faster than a date string that gets clipped at 160 px.
  • Tools as a segment matches the pattern used across the other page mockups (task, preset, format) and makes the pressed state visible without four primary buttons.
  • Empty state inside the viewport. The workspace frame stays where it is, so the page does not jump when the first shot arrives.

04Sizing and tokens

  • Header row: Capture region md (36 px), key cap 18 px mono inside the button; Settings toggle ghost sm.
  • Settings disclosure: 28 px fields; inbox path 260 px, hotkey 80 px mono; Save settings primary sm; dirty state uses the existing btn-save-dirty class and “Save settings •” label.
  • Filmstrip: 200 px wide, max-height ~420 px with its own scroll; row 46 px; thumbnail 56×36 radius 4; selected = 50 % accent border + 8 % fill (replaces the bg-accent border-l-2 block).
  • Toolbar: all 28 px (segment, ghost buttons, swatch 28×28, stroke select 56 px). Save overlay is primary sm and mounts only when the overlay is dirty; Delete is danger sm.
  • Draw surface: bg #1a1c26 is illustrative; use bg token darkened or bg-elevated. Min height 16 rem as today.
  • Motion (G33): settings disclosure and confirm strip on duration-fast / ease-out; tool segment state change is instant.
  • Tokens only (G32); heights follow G34; confirm strips use the same shape as the queue bulk bar.

06Decisions to lock before implementation

  1. Save overlay mount rule. Mount only when dirty (proposed) or always render, disabled when clean? Tests that look for capture-save on a clean shot would need the second.
  2. Hotkey key cap. Inside the Capture button label (proposed) or as a separate chip after it? Inside keeps one element; a chip is easier to hide when the hotkey is unregistered.
  3. Settings duplication. The inbox folder and hotkey also live on the Settings page. Keep the disclosure (proposed) or drop the page-level copies and link to Settings?
  4. Filmstrip name format. Strip the date prefix and show time on line two (proposed, derived from the same display_name) or keep the full name with a wider column?
  5. Tools disabled with no shot (proposed) or hidden entirely?
  6. Status line content. Today capture-status only carries errors. Showing “name · size · marks” when there is no error is new behaviour; confirm or keep it error-only.
