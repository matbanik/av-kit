Convert page: one add panel, one queue

Convert has the most form on any page: a task switch, a drop target, five presets, an advanced box, cut and extract sub-forms, an output folder with its own Save, and finally Add. Today they arrive as nine full-width blocks with the queue controls at the very bottom. This mockup keeps every control and every test id, and rearranges them so the eye travels once, top to bottom: what → which files → how → Add, then the queue.

Zone 1 · AddTask switch and encoder chip on one header line. Drop strip and Add on one line. Task-specific options as a single row underneath. Output folder in a quiet footer row.
Zone 2 · QueueIdentical to the Downloader proposal: one header row with select-all, status chips, live processor chip and the four-control toolbar; cards below.
Choices look like choicesTask, preset, cut mode and extract scope become segmented controls (sm). Only Add and Save are buttons.
ScopeComposition only. No preset value, mutation or status changes. §05 lists every test id as keep / move / change.

03Why these moves

  • Task first, files second, options third. The task decides which options exist, so it has to be the first thing the user commits to. Segmenting it and pinning it to the panel header makes the state obvious even when scrolled.
  • Add lives next to the files it adds. The label shows the count (“Add 2”) so the user never has to look down for the staged list. Staged paths become removable chips instead of a bulleted list inside the drop target.
  • Presets are a choice, not five buttons. A segmented control at sm height reads as one value; the one-line description next to it (CQ · scale · audio) replaces the need to open Advanced just to know what Balanced means.
  • Advanced is an override, and says so. The disclosure header names its relationship to the preset. Refresh GPU moves out: it is about the encoder chip, so it sits beside the chip.
  • Output folder is a footer, not a form field. It is a persisted setting the user changes rarely. A quiet row under a divider keeps it reachable without competing with per-job inputs. Save is ghost until dirty (then primary, same as today’s btn-save-dirty).
  • Encoder state is a chip. ok (green) when a GPU encoder is detected, gray for software, red for FFmpeg missing, and the same chip doubles as the Add-disabled explanation.
  • Queue matches the Downloader proposal 1:1. The four-slot toolbar, the chips-not-zeros summary, the live processor chip, the bulk bar position and the card anatomy are the same, so the two pages are learned once.
Cut and Extract are single rows. Cut = In, Out, mode; Extract = scope. Both use the same segmented pattern as Preset, so the third line of the panel changes shape but never height.

04Sizing and tokens

  • Panel column max-width 1000–1150 px, left-aligned (same cap as the Downloader proposal).
  • Page root height chain (Phase 10 input, inherited from Downloader §04): h-full min-h-0 on convert-page, flex-1 min-h-[20rem] on convert-queue-region, overflow-auto on a wrapper around QueueList only — not on the shared list container.
  • Which pane yields (same Phase 10 input): the controls above the queue are one flex min-h-0 flex-col gap-4 overflow-auto pane and the summary/toolbar footer is one flex shrink-0 flex-col gap-4 wrapper, so the controls absorb the column's height deficit. Left at the flex default the deficit is split by content height and the queue shrinks to 85px here — under the ~124px the clamp needs, which silently takes keyboard reorder away again.
  • G34 heights: task, preset, cut mode and extract scope segments and their labels at sm (28 px); Add at md (36 px); Save ghost sm, switching to primary sm when dirty; Refresh ghost sm.
  • Drop strip: min-height 52 px, dashed border-neutral, radius 6, flex 1 with min-width 300 px; while dragging over it, border and text switch to accent.
  • Staged chips: 24 px, bg-bg-elevated, monospace path, × on the right; wrap to as many rows as needed.
  • Tokens only (G32): chips reuse accent-green / accent / error / accent-red / accent-orange; card metadata in fg-muted, position numbers in bg-subtle text.
  • Motion (G33): Advanced disclosure and bulk bar use duration-fast / ease-out; processor chip dot pulses, disabled under prefers-reduced-motion.
  • Queue Zone 2 sizing is inherited unchanged from the Downloader proposal §04.

06Decisions to lock before implementation

  1. Staged-file removal. The chip × is a new action (remove one staged path before Add). Today the only way out is to Add or to re-stage. Ship it, or render the chips without × for parity?
  2. Add label. “Add 2” (count) vs plain “Add”. The count is the reason Add can sit far from the list; if the label must stay “Add”, keep the chip row directly under the strip.
  3. Output folder row. Stay on the page as a footer (proposed), or move entirely to Settings → Convert and show only a read-only path hint here? Both pages currently expose it with explicit Save.
  4. Save visual state. Ghost when clean, primary when dirty, or always primary as today? The dirty-dot label logic already exists.
  5. Encoder chip vocabulary. Drop the “Encoder:” prefix in the chip (“NVIDIA NVENC”, “Software (libx265)”, “FFmpeg missing”) or keep the exact gpuChipLabel strings? Tests assert on the text today.
  6. Refresh GPU visibility. Always visible beside the chip (proposed) vs only when Advanced is open (today). Always visible means one instance and simpler tests.
  7. Card second line content. Task meta (“Compress · Balanced · NVENC”) requires the row to know its preset and encoder; confirm the queue item wire already carries these or the line shows kind only.

Everything else is composition and can be implemented from this document plus the Downloader mockup’s Zone 2 spec without further product decisions.
