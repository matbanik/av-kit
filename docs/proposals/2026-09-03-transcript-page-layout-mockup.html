Transcript page: actions belong to the card, not the footer

The Transcript page has the smallest form in the app (one URL, one Add) and the largest button row: thirteen controls that all act on the selected channel, rendered in a wrapping line below every card. This mockup keeps the single-selection model and every one of those actions, but moves per-channel actions onto the channel card and queue-level actions into the same header row the Downloader and Convert pages use.

Zone 1 · AddChannel URL and Add on one line. The accepted-URL hint becomes the panel’s status line, so it is present without taking a row of its own.
Zone 2 · ChannelsHeader row: “Channels” + status chips + live processor chip, toolbar right: Start · Pause/Resume · Stop · ⋯. Same shape as Downloader’s four slots.
Per-channel actionsMove up/down become ▲ ▼ icon buttons beside the card’s ⋮. Compile, View compiled, Open zip, Open folder, Requeue, Retry, Remove move into the ⋮ menu, styled like the header ⋯ menu. The two most useful open as links on the card.
ScopeComposition and placement only. No API, status or enablement rule changes; controlEnabled stays the source of truth for what is greyed out.

03Why these moves

  • The selection model stays, the distance goes. Nine of the thirteen buttons already require a selected card. Putting them in that card’s ⋮ menu makes the target explicit and stops the footer row from changing width as Requeue/Retry toggle.
  • Queue-level controls go where the other pages put them. Start, Pause⇄Resume and Stop act on the processor, not a channel; they sit in the header toolbar exactly like Downloader’s Start · Pause⇄Resume · Clear finished · ⋯. Pause and Resume collapse into one slot because they are never both enabled.
  • Cards shrink to three lines because rate and ETA are only meaningful while processing, “Last: …” is only interesting for the running channel, and the two-line output tree collapses to “root · raw · compiled” with Open folder as the action.
  • Frequent actions get a link, everything else a menu. Done → View compiled / Open zip; Processing → Open folder; Failed → Retry; Cancelled → Requeue. The menu always holds the full set so nothing depends on guessing the right link.
  • Add sits beside its input. The hint is real information, so it stays, as the panel’s one status line instead of a separate row.
  • MEU-48/49 convergence. This is the card anatomy QueueCard already renders for Downloader and Convert. Adopting it here is the same primitive with a channel-specific second line, not a new component.
The header chip “3.1 transcripts/min · ETA 41 min” is the queue-level aggregate of today’s per-card rate-display / eta-display. Those two ids stay on the processing card (line 2) so tests keep a per-channel anchor; the header chip is a duplicate view, not a replacement.

04Sizing and tokens

  • Content column max-width 1000–1150 px, left-aligned; URL field flex 1 with min-width 260 px.
  • G34 heights: URL and Add at md (36 px); toolbar buttons ghost sm (28 px); card icon buttons (▲ ▼ ⋮) 26 px ghost squares as on the Downloader cards; card links are text, menu items 28 px rows.
  • Card: padding 9×12, radius 6, border border; selected = 50 % accent border + 6 % accent fill (same as QueueCard is-selected).
  • Progress bar 5 px, accent fill; accent-green when Done; the bar for a Failed channel is omitted and the error text takes the slot.
  • Status pill colors map from STATUS_COLORS: Pending/Paused status-pending, Processing accent, Done accent-green, Failed error, Cancelled neutral.
  • Menus: bg surface, bg-subtle border, radius 6, 4 px padding, destructive item in accent-red; open/close on duration-fast / ease-out (G33).
  • Tokens only (G32). Position numbers and line 3 in bg-subtle text; line 2 in fg-muted.

06Decisions to lock before implementation

  1. Toolbar slots. Start · Pause⇄Resume · Stop · ⋯ (four, parity with Downloader) or Start · Pause⇄Resume · Stop (three, no overflow because nothing goes in it yet)? Proposed: four, with “Clear finished…” in ⋯ as a new queue-level action; if that action is out of scope, ship three.
  2. Pause/Resume as one node. Two ids today. Keep both ids by swapping the id with the state (as Downloader does), or keep two DOM nodes and hide one?
  3. Card menu vs selection. Opening ⋮ on a card should also select it (so menu actions and keyboard actions agree). Confirm.
  4. Which links show on the card. Proposed: Done → View compiled + Open zip; Processing → Open folder; Failed → Retry; Cancelled → Requeue; Pending → none. Adjust or accept.
  5. Line 3 content. Last title on the processing card, output root on others. If the output tree must remain two literal paths for tests, put it in a tooltip on the root text.
  6. Multi-select. This mockup stays single-select (no checkboxes, no bulk bar). Bulk actions for Transcript are a separate MEU; the header row leaves room for the select-all checkbox when it lands.
