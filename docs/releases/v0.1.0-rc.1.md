# av-kit 0.1.0-rc.1

This is the first release candidate of av-kit and the first installer offered for download.
It is a test version: it works, it has known rough edges, and some paths haven't been checked
on this build. Both are listed below, so you can decide whether to try it now or wait.

av-kit is one Windows app that saves YouTube videos and captions, reads text aloud, shrinks
videos and marks up screenshots, all on your own PC. AI assistants can drive it through its
MCP server.

## Install

1. Download `av-kit-Setup-0.1.0-rc.1.exe` from this page. It's for Windows 10 and 11, 64-bit.
2. Run it. The installer isn't code-signed, so Windows SmartScreen may warn you. Choose
   **More info → Run anyway**. It installs for your Windows account only, into
   `%LOCALAPPDATA%\Programs\av-kit-ui`.
3. Open av-kit from the Start Menu or the Desktop shortcut.

To check your download, compare it with these values:

av-kit doesn't update itself. To move to a later version, download that version's installer.

Uninstalling removes the app and its shortcuts. Your settings and history stay in
`%LOCALAPPDATA%\av-kit`, your voice models stay in `%USERPROFILE%\.avkit\models`, and your downloads
and converted files stay where you saved them. Delete them yourself if you want them gone.

## What's fixed

- **The window could freeze during busy work.** Every piece of backend output ran a blocking
  process check. That check now runs only when the backend reports it's ready.
- **The first conversion on a new PC always failed.** Nothing created Convert's output folder, so
  the job ended with `ffmpeg exited 4294967294`. av-kit now creates the folder before it starts.
- **A large screenshot could cut off your AI assistant's connection to av-kit.** `avkit_capture image`
  now refuses a file over 7.8 MB with a clear error and tells the assistant to open the file
  instead, and the connection keeps working. An assistant can't see a shot that large as an image.
- **The encoder chosen for one job was ignored.** Convert's Encoder dropdown and `avkit_convert add`'s
  `gpu_preference` had no effect, and only **Settings → Convert → GPU preference** counted. A job now
  runs the encoder it asked for, and a job that asks for nothing still follows the setting.
- **Closing the window could show a JavaScript error.** With **Close to tray** off, backend output
  arriving after the window closed could stop the app behind an `Object has been destroyed` dialog.
  That output now stays in the app's log and nothing is shown.

## Transcript isn't verified on this build

`YOUTUBE-CAPTIONS-IP-BLOCK`: YouTube is blocking caption requests from the network this build was
tested on. A direct request through av-kit's own code gets `YouTube is blocking requests from your
IP`, so no captions arrive and the step that combines them has nothing real to work on.

- The Transcript path, from fetching captions to the combined files, hasn't run end to end on this
  build. It last ran on an earlier development build, before the block.
- If you see that message, YouTube is limiting your network, not your copy of av-kit. Try again
  later or from another network.

This release goes out with that gap by the maintainer's decision. Once the release is public, the
maintainer will recheck Transcript in an app installed from this page, and this section comes out
if that check shows real captions.

## How this build was tested

This build was tested on one Windows 11 PC that already had av-kit's data on it.

The installer itself went through a silent install and uninstall:

- The installed app started, reached its backend, found its bundled FFmpeg and showed the Settings
  page.
- The installed backend ran a first conversion into a folder that didn't exist yet.
- On that PC, which has an NVIDIA GPU, a job set to Software ran `libx265` while the default job ran
  `hevc_nvenc`. That was through the backend API. The Encoder dropdown itself is covered by automated
  tests, not by a run of the installed window.
- Uninstalling left no program files, shortcuts or startup entries behind, and kept the data folder.

The build's unpacked files, before that:

- The MCP server started and reported this version.
- A copy of the backend generated speech from a voice model that was already downloaded, with its
  network proxies pointed at a dead port.

Not checked by those runs: Windows 10, a real download, a real F2 capture and a first voice model
download.

The maintainer then ran this page's installer, with the SHA-256 above, on a Windows 10 Pro PC
(build 19045) with no earlier av-kit files. Installing, FFmpeg, a first voice model download (ONNX
FP16) with generated speech played back, a real F2 capture with an arrow and pixelate, and a real
video download with **Open file** all worked.

On Convert, only audio extraction was tried, from a local video into the default output folder. It
wrote the right audio but named an AAC file `.mka`. Compressing and cutting weren't tried on that
PC. (`CONVERT-EXTRACT-STREAM-INDEX-MISMATCH`)

Uninstalling removed the app and its shortcuts, and `%LOCALAPPDATA%\av-kit` stayed as expected. It
also left the voice models in `%USERPROFILE%\.avkit\models`, a 340 MB copy of the installer in
`%LOCALAPPDATA%\av-kit-ui-updater`, and the app window's data in `%APPDATA%\av-kit-ui`.
(`MODELS-DIR-DOCS-AND-PROBE-MISMATCH`, `UNINSTALL-LEAVES-INSTALLER-COPY`)

Two things failed:

- The PyTorch FP32 voice model downloaded 327 MB and then couldn't load, because this build has no
  PyTorch runtime. Use an ONNX model. (`TTS-PYTORCH-OFFERED-WITHOUT-RUNTIME`)
- Transcript failed with no explanation on screen. That PC is on the same network YouTube is
  blocking, so this doesn't show whether it works elsewhere. (`YOUTUBE-CAPTIONS-IP-BLOCK`,
  `TRANSCRIPT-FAILED-NO-REASON`)

## Known problems

None of these are fixed in this release. The names in brackets match
[the project's known issues list](https://github.com/matbanik/av-kit/blob/main/.agent/context/known-issues.md).

**Transcript**

- Every transcript's title is its video ID, including in the combined files, which makes them
  harder to navigate. (`TRANSCRIPT-TITLE-IS-VIDEO-ID`)
- Files from a playlist run show the playlist's title as the channel name.
  (`TRANSCRIPT-CHANNEL-IS-PLAYLIST-NAME`)
- Adding a whole channel returned an error once, after about 8 minutes of listing its videos. It
  was seen once and the cause isn't known. (`TRANSCRIPT-ADD-CHANNEL-422`)

**Downloader**

- A download row shows the quality you asked for, not the quality you got. When YouTube limits
  quality, the file can be lower than the row says. (`DOWNLOAD-ROW-SHOWS-REQUESTED-QUALITY`)

**Text to speech**

- The 13 Japanese and Mandarin voices are listed but can't generate. (`TTS-JA-ZH-G2P-EXTRAS`)
- Spanish, French, Hindi, Italian and Portuguese voices need eSpeak NG installed separately, and
  have never been run end to end with the real program. They may mispronounce words or fail.
  (`TTS-ESPEAK-LIVE-PATH-UNVERIFIED`)
- Speech runs on the processor only, in every case. Settings still offers `cuda` and `mps`, which
  this build can't use, and choosing `cuda` hasn't been tested, so leave it on `auto` or `cpu`.
  (`TTS-DEVICE-OPTIONS-IN-CPU-BUILD`)
- Audio files get random ID names, so finding a clip later can mean opening each one.
  (`TTS-AUDIO-RANDOM-FILE-NAMES`)

**Capture**

- If the app crashes just after saving a capture an AI assistant asked for, the request isn't
  marked complete. The image is saved, and the request expires on its own after 2 minutes.
  (`CAPTURE-JOURNAL-VOLATILE`)

**Cosmetic**

- The speech progress label reads `Segments 0/1000` whatever the text's length. The bar itself is
  right. (`TTS-SEGMENTS-LABEL-IS-PROGRESS-SCALE`)
- Convert's queue numbers aren't renumbered when jobs leave, though the order holds.
  (`CONVERT-POSITIONS-NOT-RENUMBERED`)
- An edit under Convert's Advanced can snap back to the preset's value if settings load late or the
  default preset changes. (`CONVERT-ADVANCED-EDIT-REPLACED`)
- A cut job's row shows its times in raw milliseconds. (`CONVERT-CUT-TIME-RAW-MS`)
- An audio extract is labelled with a video encoder. The file is right.
  (`CONVERT-EXTRACT-ENCODER-LABEL`)
- An empty gap sits under Advanced on the Downloader page. (`DOWNLOADER-ADVANCED-PANEL-GAP`)

## Report a problem

Open an issue at <https://github.com/matbanik/av-kit/issues>. These details help:

- the version (`0.1.0-rc.1`) and your Windows version
- what you did, what you expected and what happened
- the exact error text, or a screenshot with anything private hidden

Please don't attach files from `%LOCALAPPDATA%\av-kit`. That folder holds your history and a
private access token.
