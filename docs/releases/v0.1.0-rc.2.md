# av-kit 0.1.0-rc.2

This is the second release candidate of av-kit. It replaces `0.1.0-rc.1` and fixes what people
found in that build. It is still a test version: some paths haven't been checked on this build,
and some known problems remain. Both are listed below, so you can decide whether to try it now or
wait.

av-kit is one Windows app that saves YouTube videos and captions, reads text aloud, shrinks
videos and marks up screenshots, all on your own PC. AI assistants can drive it through its
MCP server.

## Install

1. Download `av-kit-Setup-0.1.0-rc.2.exe` from this page. It's for Windows 10 and 11, 64-bit.
2. Run it. The installer is unsigned, so Windows SmartScreen may warn you. Choose
   **More info → Run anyway**. It installs for your Windows account only, into
   `%LOCALAPPDATA%\Programs\av-kit-ui`. If `0.1.0-rc.1` is installed, this installs over it and
   keeps your settings, history and voice models.
3. Open av-kit from the Start Menu or the Desktop shortcut.

To check your download, compare it with these values:

| | |
|---|---|
| Size | 340,362,828 bytes |
| SHA-256 | `547b1f5019e79f2b2a44fbc79aedc16c45bf26c753c1ada9845dcdd8037f74c8` |

av-kit doesn't update itself. To move to a later version, download that version's installer.

Uninstalling removes the app, its shortcuts and the installer's own copy in
`%LOCALAPPDATA%\av-kit-ui-updater`. Your settings and history stay in `%LOCALAPPDATA%\av-kit`, the
app window's data stays in `%APPDATA%\av-kit-ui`, your voice models stay in
`%USERPROFILE%\.avkit\models`, and your downloads and converted files stay where you saved them.
Delete them yourself if you want them gone.

## What's fixed

**Install and uninstall**

- **Uninstalling left a 340 MB copy of the installer behind.** It now removes that copy from
  `%LOCALAPPDATA%\av-kit-ui-updater`, except while an installer is updating the app in place.
- **The setup check looked for voice models in the wrong folder, and created it.** It now checks
  `%USERPROFILE%\.avkit\models`, where av-kit keeps them, and no longer creates an empty folder.
- **The FFmpeg download script returned the wrong exit codes on failure.** This only affects
  building av-kit; each failure now returns its documented code.

**Transcript**

- **A failed or skipped transcript gave no reason.** Each one now says why: YouTube blocked the
  request, the video has no captions, the video is unavailable, or another error. The full error
  always goes to the Console.
- **A YouTube block kept the job asking for captions.** When a block outlasts the retries, the job
  now pauses with a message and waits for **Resume**. The requests-per-hour limit now covers every
  caption request, retries included.
- **Every transcript's title was its video ID.** Transcripts and the combined files now use the
  video's real title.
- **Files from a playlist showed the playlist's title as the channel.** They now show the video's
  channel.

**Text to speech**

- **The PyTorch FP32 model downloaded 327 MB and then couldn't load.** This build has no PyTorch
  runtime, so the model is listed but disabled, with "This build can't run PyTorch models. Choose an
  ONNX model.", and av-kit refuses to download or load it.
- **Settings offered `cuda` and `mps`, which this build can't use.** The device options are now
  `auto` and `cpu`. A stored `cuda` shows as `auto`.
- **A model that failed to load replaced the one that was working.** A failed load now keeps the
  current model. Console lines show your home folder as `~`.
- **A fresh install preselected ONNX FP16, which fails on some sentences.** It now preselects ONNX
  INT8, which generated all 149 sentences of the test set. FP16 is still offered; see Known
  problems.

**Convert**

- **An AAC audio extract was named `.mka`.** It's now `.m4a`.
- **"All audio streams" skipped the first audio track.** It now includes every track, a track that
  doesn't exist fails with a clear error, and extract rows no longer show a video encoder.

**Downloader**

- **A row showed the quality you asked for, not the quality you got.** It now shows what arrived,
  for example `360p (asked 1080p)`.
- **A bare channel URL listed the channel's tabs instead of its videos.** It now queues the
  channel's videos.
- **A video link from inside a playlist downloaded the whole playlist.** It now downloads only that
  video.
- **The Console's startup line showed the database's full path.** It no longer does.

**Display**

- **Light theme's accent labels were below the 4.5:1 contrast that WCAG AA asks for.** They now read
  at 7.27:1.

## Corrections to the 0.1.0-rc.1 notes

- Voice models live in `%USERPROFILE%\.avkit\models`. Some of the project's earlier instructions,
  and the setup check fixed above, named another folder. (`MODELS-DIR-DOCS-AND-PROBE-MISMATCH`)
- The clean-machine install, the real F2 capture and the first voice model download were checked by
  the maintainer on 2026-11-04, on a Windows 10 Pro PC with `0.1.0-rc.1`. They haven't been repeated
  on this build yet; the maintainer repeats them before this release is published.

## Transcript on this build

`YOUTUBE-CAPTIONS-IP-BLOCK`: when `0.1.0-rc.1` was tested, YouTube blocked caption requests from
the test network, and a direct request through av-kit's own code got `YouTube is blocking requests
from your IP`. On 2026-11-09 the project's live audit, on the same network, fetched one video's
captions through av-kit's backend and combined them, so the block wasn't in effect that day.

- The installed app's Transcript path, from fetching captions to the combined files, hasn't run end
  to end on this build.
- Transcript hasn't been tried from another network.
- If YouTube blocks your network, av-kit pauses the job and shows the message. Try again later or
  from another network, then choose **Resume**.

The maintainer rechecks Transcript in an app installed from this page before publishing, and this
section comes out if that check shows real captions. If that check isn't run, the release goes out
with this gap by the maintainer's decision.

## How this build was tested

This build was tested on one Windows 11 PC with an NVIDIA GPU that already had av-kit's data on it.
It was built from a clean source tree with no network access, from FFmpeg and Electron files already
on that PC, and the installer's size and SHA-256 were recorded at build time.

The build's unpacked files:

- The bundled backend and FFmpeg passed the release smoke check, which also confirmed that a backend
  holding the wrong speech libraries is caught.
- The MCP server started and reported `0.1.0-rc.2`.
- A copy of the backend generated speech from a voice model that was already downloaded, with its
  network proxies pointed at a dead port.
- FFmpeg reported build `n8.1.3-27-g8dca1586f4`. A default conversion ran `hevc_nvenc`, and a job set
  to Software ran `libx265`.

The installer, through four silent install and uninstall rounds:

- `0.1.0-rc.1` installed and uninstalled, leaving its installer copy behind as expected of that
  version.
- This installer installed on its own, passed the release smoke check in the install folder, and
  the installed app started, reached its backend and showed the Settings page. Its uninstall removed
  the installer copy.
- This installer over `0.1.0-rc.1`, and this installer over itself, both started and uninstalled
  cleanly.
- Every uninstall left no program files behind and left `%APPDATA%\av-kit-ui` and
  `%LOCALAPPDATA%\av-kit` unchanged.

A copy of the installed backend:

- With no voice models, the PyTorch FP32 model was listed as unavailable, and its download and load
  were refused without touching the models folder.
- ONNX INT8 generated all 149 sentences of the test set, each with real audio.

The project's full test suite and the live audit of every MCP tool passed: 1,357 Python tests,
1,183 UI tests, 470 MCP server tests, 190 end-to-end tests of the desktop app, and 99 of 99 audited
MCP tool calls. The check's last line reads `session-gate: all steps exit 0`.

Not checked by those runs: Windows 10, a clean PC, a real video download, a real F2 capture and a
first voice model download on this build. The maintainer checks these on a clean PC before
publishing.

## Known problems

None of these are fixed in this release. The names in brackets match
[the project's known issues list](https://github.com/matbanik/av-kit/blob/main/.agent/context/known-issues.md).

**Transcript**

- The installed app's Transcript path isn't verified on this build; see "Transcript on this build"
  above. (`YOUTUBE-CAPTIONS-IP-BLOCK`)
- On a channel whose listing gives no channel name, a video title with certain broken characters
  could stop a transcript job from being created. It was found in the code and hasn't been seen in
  use. (`TRANSCRIPT-UNCLEANED-TITLE-FALLBACKS`)
- Adding a whole channel returned an error once, after about 8 minutes of listing its videos. It
  was seen once and the cause isn't known. (`TRANSCRIPT-ADD-CHANNEL-422`)

**Text to speech**

- ONNX FP16 fails on some ordinary sentences with `generated audio must be finite`. It failed 12 of
  the 149 test sentences. Use ONNX INT8, which a fresh install now picks, or ONNX FP32.
  (`TTS-ONNX-FP16-NONFINITE-AUDIO`)
- The 13 Japanese and Mandarin voices are listed but can't generate. (`TTS-JA-ZH-G2P-EXTRAS`)
- Spanish, French, Hindi, Italian and Portuguese voices need eSpeak NG installed separately, and
  have never been run end to end with the real program. They may mispronounce words or fail.
  (`TTS-ESPEAK-LIVE-PATH-UNVERIFIED`)
- Audio files get random ID names, so finding a clip later can mean opening each one.
  (`TTS-AUDIO-RANDOM-FILE-NAMES`)
- The job's status label is below 4.5:1 contrast in both themes. (`TTS-STATUS-PILL-BELOW-AA-CONTRAST`)

**Capture**

- If the app crashes just after saving a capture an AI assistant asked for, the request isn't
  marked complete. The image is saved, and the request expires on its own after 2 minutes.
  (`CAPTURE-JOURNAL-VOLATILE`)
- If an AI assistant changes a capture setting while you have an unsaved capture settings edit
  open, saving your edit writes the old values of the other capture settings back over the
  assistant's change. (`SETTINGS-DRAFT-STALE-BASELINE`)

**Console**

- A Console line that names your home folder in its short Windows (8.3) form shows it as written,
  not as `~`. (`CONSOLE-HOME-SCRUB-SHORT-FORM`)

**Cosmetic**

- The speech progress label reads `Segments 0/1000` whatever the text's length. The bar itself is
  right. (`TTS-SEGMENTS-LABEL-IS-PROGRESS-SCALE`)
- Convert's queue numbers aren't renumbered when jobs leave, though the order holds.
  (`CONVERT-POSITIONS-NOT-RENUMBERED`)
- An edit under Convert's Advanced can snap back to the preset's value if settings load late or the
  default preset changes. (`CONVERT-ADVANCED-EDIT-REPLACED`)
- A cut job's row shows its times in raw milliseconds. (`CONVERT-CUT-TIME-RAW-MS`)
- A cut job is labelled with an encoder it doesn't use. The file is right.
  (`CONVERT-CUT-ENCODER-LABEL`)
- An empty gap sits under Advanced on the Downloader page. (`DOWNLOADER-ADVANCED-PANEL-GAP`)

## Licences

av-kit's own code is under the [MIT licence](https://github.com/matbanik/av-kit/blob/main/LICENSE).
The components bundled with it keep their own licences:

- `THIRD_PARTY_LICENSES.txt`, attached to this release and installed with the app, holds the
  licence text of what the build actually ships. It's generated from the build.
- `THIRD_PARTY_NOTICES.md`, installed with the app, covers the main components in plain language.
- Electron's and Chromium's licences sit in the install folder.

FFmpeg ships as a separate program that av-kit runs, licensed under the GPL, version 3. This is
the same build as in `0.1.0-rc.1`: `n8.1.3-27-g8dca1586f4` (64-bit Windows, GPL, BtbN release
`autobuild-2026-10-31-12-59`).

That stock build also links libdvdread and libdvdnav, and through them libdvdcss, a library for
reading encrypted DVDs, into `ffmpeg.exe`. av-kit never uses DVD input. The maintainer chose to keep
the stock build rather than build FFmpeg without them, and hasn't had the legal side of shipping
libdvdcss assessed. (`FFMPEG-LIBDVDCSS-BUNDLED`)

FFmpeg's complete corresponding source is attached to this release as
`av-kit-0.1.0-rc.1-ffmpeg-source.tar.xz`. It keeps its `0.1.0-rc.1` name because the FFmpeg build
didn't change, so it's the same file, byte for byte, that `0.1.0-rc.1` carries. You don't need it to
use av-kit. Its `README.md` says what's inside and names the few things the build's scripts don't
pin.

## Report a problem

Open an issue at <https://github.com/matbanik/av-kit/issues>. These details help:

- the version (`0.1.0-rc.2`) and your Windows version
- what you did, what you expected and what happened
- the exact error text, or a screenshot with anything private hidden

Please don't attach files from `%LOCALAPPDATA%\av-kit`. That folder holds your history and a
private access token.
