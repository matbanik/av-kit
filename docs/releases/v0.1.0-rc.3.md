# av-kit 0.1.0-rc.3

This is the third release candidate of av-kit. It replaces `0.1.0-rc.1`, the last published build.
`0.1.0-rc.2` was built and tested but never published; everything it fixed is in this build too,
and [its notes](https://github.com/matbanik/av-kit/blob/main/docs/releases/v0.1.0-rc.2.md) list
those fixes. This is still a test version: some paths haven't been checked on this build, and some
known problems remain. Both are listed below, so you can decide whether to try it now or wait.

av-kit is one Windows app that saves YouTube videos and captions, reads text aloud, shrinks
videos and marks up screenshots, all on your own PC. AI assistants can drive it through its
MCP server.

## Install

1. Download `av-kit-Setup-0.1.0-rc.3.exe` from this page. It's for Windows 10 and 11, 64-bit.
2. Run it. The installer is unsigned, so Windows SmartScreen may warn you. Choose
   **More info → Run anyway**. It installs for your Windows account only, into
   `%LOCALAPPDATA%\Programs\av-kit-ui`. If an earlier av-kit is installed, this installs over it
   and keeps your settings, history and voice models.
3. Open av-kit from the Start Menu or the Desktop shortcut.

To check your download, compare it with these values:

The installer and the app now name **focalia.ai** as their publisher. The copyright holder is
unchanged.

av-kit doesn't update itself. To move to a later version, download that version's installer.

Uninstalling removes the app, its shortcuts and the installer's own copy in
`%LOCALAPPDATA%\av-kit-ui-updater`. Your settings and history stay in `%LOCALAPPDATA%\av-kit`, the
app window's data stays in `%APPDATA%\av-kit-ui`, your voice models stay in
`%USERPROFILE%\.avkit\models`, and your downloads and converted files stay where you saved them.
Delete them yourself if you want them gone.

## What's fixed

These were found by testing `0.1.0-rc.2` on a freshly installed Windows 11 PC.

**Text to speech**

- **The spaCy download failed on a fresh Windows install.** Windows hadn't yet loaded the
  certificates that GitHub's download servers use, so the download couldn't verify them. It now
  verifies against the certificate list av-kit ships, as av-kit's other downloads already did.
- **A voice model download sat at 0% until the whole file had arrived.** The bar now moves as the
  file downloads.
- **Audio files had random ID names.** A file is now named from the first three words of its text
  and its voice, for example `hello-and-welcome-af_heart.mp3`. A name already in use gets `-2`,
  `-3` and so on.
- **An MP3 job left a WAV file beside the MP3.** The WAV is now removed once the MP3 is made. A WAV
  job still leaves only the WAV.

**Transcript**

- **Adding a channel or playlist was slow and showed nothing while it worked.** It now reads the
  channel's video list in seconds instead of opening every video first. The page says it's adding,
  then how many videos it queued.
- **A video YouTube blocked showed nothing while av-kit waited to retry.** Its card now shows the
  retry and how long until it. If the block outlasts the retries, the job still pauses with a
  message and waits for **Resume**.

**Console**

- **A level button showed only lines of that exact level.** Choosing a level now shows that level
  and every more severe one, so **DEBUG** shows everything and **ERROR** shows errors and critical
  lines.
- **Settings → Log level was saved but did nothing.** The Console now opens at that level, which
  is INFO unless you change it. A button you click still wins until the app restarts.

## What's new

**Capture, for AI assistants**

- An assistant can look at part of a capture. The capture's image request takes an optional region
  (`x`, `y`, `width`, `height`) and fits it inside `max_edge`, and the answer says where the
  returned pixels sit in the original. No file is written.
- An assistant can bring in any local image. The capture action's `import` mode copies a PNG, JPEG
  or WebP file into the capture inbox as a new shot, so crop, annotate and the region view work on
  it. The original file is never changed.

## Transcript on this build

`YOUTUBE-CAPTIONS-IP-BLOCK`: when this build's fixes were tested on 2026-11-09, YouTube blocked
caption requests from the test network. A request from another PC on the same network was blocked
too, so it wasn't caused by this build.

- The installed app's Transcript path, from fetching captions to the combined files, hasn't run end
  to end on this build.
- Transcript hasn't been tried from another network.
- If YouTube blocks your network, av-kit pauses the job and shows the message. Try again later or
  from another network, then choose **Resume**.

## How this build was tested

The fixes were tested by the maintainer on a Windows 11 virtual machine restored to a clean state
before each round, using builds of `0.1.0-rc.2` with these fixes added. The spaCy download, the
model download progress, the TTS file names, the Transcript add and the Console levels were checked
there by hand. The MP3-only output and the publisher were fixed last; their tests and this build's
files confirm them, but they haven't been checked by hand. An independent code review of the fixes
found no blocking problem, and its one note was fixed.

This installer was built afterwards from the release commit, which also holds the capture work
under "What's new". It was built from a clean source tree with no network access, from FFmpeg and
Electron files already on the build PC, and its size and SHA-256 were recorded at build time.

The build's unpacked files:

- The bundled backend and FFmpeg passed the release smoke check, which also confirmed that a backend
  holding the wrong speech libraries is caught. The backend reported `0.1.0rc3`.
- FFmpeg reported build `n8.1.3-27-g8dca1586f4`.
- The bundled backend holds each fix above, and the app's files hold the Console and Transcript
  changes and the new publisher.

The installer, on a Windows 11 virtual machine restored to a clean state:

- It arrived with the same SHA-256 as above.
- A silent install put the app, its backend, FFmpeg and the licence list in place. Windows' Apps
  list showed `av-kit 0.1.0-rc.3`, version `0.1.0-rc.3`, publisher focalia.ai.
- A silent uninstall removed the app, its Apps entry and the installer's copy in
  `%LOCALAPPDATA%\av-kit-ui-updater`.

On the release commit, 1,192 UI tests and 479 MCP server tests passed, and 1,447 Python tests
passed. One more Python test failed: a self-test of the project's own workflow tooling, which reads
the temporary folder's location as part of its expected message. It doesn't touch the app. The
desktop app's end-to-end tests and the live audit of every MCP tool weren't rerun on this build.

Not checked on this exact installer: Windows 10, a real video download, a real F2 capture and a
first voice model download.

## Known problems

None of these are fixed in this release. The names in brackets match
[the project's known issues list](https://github.com/matbanik/av-kit/blob/main/.agent/context/known-issues.md).

**Transcript**

- The installed app's Transcript path isn't verified on this build; see "Transcript on this build"
  above. (`YOUTUBE-CAPTIONS-IP-BLOCK`)
- On a channel whose listing gives no channel name, a video title with certain broken characters
  could stop a transcript job from being created. It was found in the code and hasn't been seen in
  use. (`TRANSCRIPT-UNCLEANED-TITLE-FALLBACKS`)
- Adding a whole channel returned an error once, after about 8 minutes of listing its videos. It
  was seen once and the cause isn't known. Adding a channel now reads its list in seconds, but
  whether the error can still happen isn't known. (`TRANSCRIPT-ADD-CHANNEL-422`)

**Text to speech**

- ONNX FP16 fails on some ordinary sentences with `generated audio must be finite`. It failed 12 of
  the 149 test sentences. Use ONNX INT8, which a fresh install picks, or ONNX FP32.
  (`TTS-ONNX-FP16-NONFINITE-AUDIO`)
- The 13 Japanese and Mandarin voices are listed but can't generate. (`TTS-JA-ZH-G2P-EXTRAS`)
- Spanish, French, Hindi, Italian and Portuguese voices need eSpeak NG installed separately, and
  have never been run end to end with the real program. They may mispronounce words or fail.
  (`TTS-ESPEAK-LIVE-PATH-UNVERIFIED`)
- The job's status label is below 4.5:1 contrast in both themes. (`TTS-STATUS-PILL-BELOW-AA-CONTRAST`)

**Capture**

- If the app crashes just after saving a capture an AI assistant asked for, the request isn't
  marked complete. The image is saved, and the request expires on its own after 2 minutes.
  (`CAPTURE-JOURNAL-VOLATILE`)
- A phone or camera photo whose file says to show it turned (most portrait photos) is recorded at
  its stored width and height when it reaches the inbox by the folder scan. Marks and regions then
  land turned against what you see. Images brought in by an assistant's `import` are saved upright
  and aren't affected. (`CAPTURE-EXIF-SCANNED-ORIENTATION`)
- If an AI assistant changes a capture setting while you have an unsaved capture settings edit
  open, saving your edit writes the old values of the other capture settings back over the
  assistant's change. (`SETTINGS-DRAFT-STALE-BASELINE`)

**Console**

- A Console line that names your home folder in its short Windows (8.3) form shows it as written,
  not as `~`. (`CONSOLE-HOME-SCRUB-SHORT-FORM`)

**Cosmetic**

- The speech progress label reads `Segments 0/1000` whatever the text's length. The bar itself is
  right. (`TTS-SEGMENTS-LABEL-IS-PROGRESS-SCALE`)
- Convert's queue numbers aren't renumbered when jobs leave, though the order holds.
  (`CONVERT-POSITIONS-NOT-RENUMBERED`)
- An edit under Convert's Advanced can snap back to the preset's value if settings load late or the
  default preset changes. (`CONVERT-ADVANCED-EDIT-REPLACED`)
- A cut job's row shows its times in raw milliseconds. (`CONVERT-CUT-TIME-RAW-MS`)
- A cut job is labelled with an encoder it doesn't use. The file is right.
  (`CONVERT-CUT-ENCODER-LABEL`)
- An empty gap sits under Advanced on the Downloader page. (`DOWNLOADER-ADVANCED-PANEL-GAP`)

## Licences

av-kit's own code is under the [MIT licence](https://github.com/matbanik/av-kit/blob/main/LICENSE).
The components bundled with it keep their own licences:

- `THIRD_PARTY_LICENSES.txt`, attached to this release and installed with the app, holds the
  licence text of what the build actually ships. It's generated from the build.
- `THIRD_PARTY_NOTICES.md`, installed with the app, covers the main components in plain language.
- Electron's and Chromium's licences sit in the install folder.

FFmpeg ships as a separate program that av-kit runs, licensed under the GPL, version 3. This is
the same build as in `0.1.0-rc.1`: `n8.1.3-27-g8dca1586f4` (64-bit Windows, GPL, BtbN release
`autobuild-2026-10-31-12-59`).

That stock build also links libdvdread and libdvdnav, and through them libdvdcss, a library for
reading encrypted DVDs, into `ffmpeg.exe`. av-kit never uses DVD input. The maintainer chose to keep
the stock build rather than build FFmpeg without them, and hasn't had the legal side of shipping
libdvdcss assessed. (`FFMPEG-LIBDVDCSS-BUNDLED`)

FFmpeg's complete corresponding source is attached to this release as
`av-kit-0.1.0-rc.1-ffmpeg-source.tar.xz`. It keeps its `0.1.0-rc.1` name because the FFmpeg build
didn't change, so it's the same file, byte for byte, that `0.1.0-rc.1` carries. You don't need it to
use av-kit. Its `README.md` says what's inside and names the few things the build's scripts don't
pin.

## Report a problem

Open an issue at <https://github.com/matbanik/av-kit/issues>. These details help:

- the version (`0.1.0-rc.3`) and your Windows version
- what you did, what you expected and what happened
- the exact error text, or a screenshot with anything private hidden

Please don't attach files from `%LOCALAPPDATA%\av-kit`. That folder holds your history and a
private access token.
