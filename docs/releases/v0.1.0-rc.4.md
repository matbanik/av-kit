# av-kit 0.1.0-rc.4

This is the fourth release candidate of av-kit. It replaces `0.1.0-rc.3`. It's still a test
version: some paths haven't been checked on this build, and some known problems remain. Both are
listed below, so you can decide whether to try it now or wait.

av-kit is one Windows app that saves YouTube videos and captions, reads text aloud, shrinks
videos and marks up screenshots, all on your own PC. AI assistants can drive it through its
MCP server.

## Install

1. Download `av-kit-Setup-0.1.0-rc.4.exe` from this page. It's for Windows 10 and 11, 64-bit.
2. Run it. The installer is unsigned, so Windows SmartScreen may warn you. Choose
   **More info → Run anyway**. It installs for your Windows account only, into
   `%LOCALAPPDATA%\Programs\av-kit-ui`. If an earlier av-kit is installed, this installs over it
   and keeps your settings, history and voice models.
3. Open av-kit from the Start Menu or the Desktop shortcut.

To check your download, compare it with these values:

| | |
|---|---|
| Size | 371,756,139 bytes |
| SHA-256 | `4d8879cb096b1fcf0eebd8025276811285ecc4c65dedfb705349ff6472ea79e2` |

The installer is about 31 MB larger than `0.1.0-rc.3`, mostly because it now includes Deno (see
"Downloader" below).

av-kit doesn't update itself. To move to a later version, download that version's installer.

Uninstalling removes the app, its shortcuts and the installer's own copy in
`%LOCALAPPDATA%\av-kit-ui-updater`. Your settings and history stay in `%LOCALAPPDATA%\av-kit`, the
app window's data stays in `%APPDATA%\av-kit-ui`, your voice models stay in
`%USERPROFILE%\.avkit\models`, and your downloads and converted files stay where you saved them.
Delete them yourself if you want them gone.

## What's new

**A quick start on every page**

- Each page's **How it works** card now opens with a short quick start: one sentence about the
  page, four or five numbered steps, and a screenshot of the page with the same numbers on it.
  The screenshot follows the light or dark theme. The longer topics are still there, under
  **More about this page**. The card stays closed until you open it, and **F1** opens it as before.

**Capture editor**

- **Crop.** The Crop tool puts a box with eight handles over the image, with aspect presets and
  exact X, Y, width and height fields. **Save as copy** saves the crop as a new shot. The original
  stays as it was.
- **Import.** Drop image files on the Capture page, choose **Import image...**, or press
  **Ctrl+V** with an image on the clipboard. PNG, JPEG and WebP files are accepted.
- **New marks.** A line (an arrow with no head), a double-headed arrow, an ellipse, a numbered
  step badge, and a solid redact box, black by default. **Ctrl+D** duplicates the selected mark.
- **Copy image.** **Copy image** and **Ctrl+C** on the image copy the shot with its marks, saved
  or not.
- **Text** can hold more than one line: **Shift+Enter** starts a new line and **Enter** finishes.
- **Faster marking.** The tool stays armed after each mark (turn **Lock** off to go back to
  Select). Each tool has a letter key, and each tool remembers its own colour and size. A colour
  applies as soon as you pick it.
- The Pixelate button's eraser is now called the **Smart eraser**.

**Capture, for AI assistants**

- An assistant can crop a capture into a new shot, and export a resized or re-encoded copy
  (PNG, JPEG or WebP).
- An assistant can read a local video's length, size and streams, take still frames from it into
  the capture inbox, and make one labelled grid sheet of a span of the video, then narrow the span
  to look closer. The video is read where it is and never changed or uploaded.

**Downloader**

- **A failed download says why.** A failed or age-restricted card gives one short reason, such as
  refused, no format, cookies needed or the file couldn't be written. For any other failure it
  shows the first line of yt-dlp's own message.
- **Fewer refused downloads.** yt-dlp now picks its YouTube clients itself. If that fails on the
  client side, av-kit tries once more with a fixed set of clients, and the Console shows each
  attempt.
- **Deno is included.** YouTube now asks downloaders to solve a script challenge. The installer
  ships Deno, a JavaScript runtime, and the app gives it to yt-dlp with yt-dlp's challenge
  solver. Settings shows which runtime is in use, or says that none was found.
- **MP3 is really MP3.** An audio download set to MP3 is converted to MP3 with the bundled FFmpeg
  after it lands, and the original download is removed.
- yt-dlp's warnings and errors now always reach the Console.

## What's fixed

**Text to speech**

- **ONNX FP16 failed on some ordinary sentences** with `generated audio must be finite`. It no
  longer fails on the 149 test sentences. A fresh install still picks ONNX INT8.
- **The progress label read `Segments 0/1000`** whatever the text's length. It now shows a
  percentage.
- **The job's status label was hard to read.** Every status now reads at 4.5:1 contrast or more
  in both themes.

**Convert and Downloader queues**

- **Pause** waits for the current job to end, so the button now reads **Pause after this job**, and
  then **Pausing...** until the queue stops. **Cancel** still stops the running job at once.
- **Cancel** is turned off while the queue is paused, because no job runs then.
- Convert's queue cards are numbered 1, 2, 3 as shown, and a waiting card says where it is in line.
- A cut job's row shows its times as `HH:MM:SS.mmm`, not raw milliseconds, and it no longer names
  an encoder it doesn't use.
- Adding the same file to Convert again while its first job hasn't finished now gives the second
  job its own output name, so it no longer overwrites the first job's output.
- An edit under Convert's **Advanced** no longer snaps back when settings load late or the default
  preset changes.
- The empty gap under **Advanced** on the Downloader page is gone.

**Capture**

- A phone or camera photo that is stored turned (most portrait photos) is now shown, marked,
  cropped and saved the way you see it.
- A damaged, half-written or non-image file in the capture inbox no longer breaks the capture
  list. It's skipped and tried again on the next scan.
- If an AI assistant changes a capture setting while you have an unsaved capture settings edit
  open, saving your edit no longer writes the old values back over the assistant's change.
- The text mark's background box in the editor now matches the saved image more closely.
- Taking a frame at a time past a video's last frame no longer fails now and then on a busy PC.

**Transcript**

- A video or channel title with broken characters could stop a transcript job from being created.
  Such titles are now cleaned first.
- A pause or stop now ends Transcript's waits between videos, between batches and before a retry
  within a second.

**App and Console**

- A Console line that names your home folder in its short Windows (8.3) form now shows it as `~`.
- **F1** or **Ctrl+O** pressed while the Capture or Convert page is still loading is now kept and
  acts once when the page appears.
- The app could, rarely, send its first request to the backend before the backend was listening.
  The backend now listens before it says it's ready.

## How this build was tested

This installer was built from the release commit in a clean source tree with no network access,
from FFmpeg, Deno and Electron files already on the build PC, each checked against its pinned
SHA-256. Its size and SHA-256 were recorded at build time, and the build's inputs were checked
against the release commit afterwards.

The build's unpacked files:

- The bundled backend and FFmpeg passed the release smoke check, which also confirmed that a
  backend holding the wrong speech libraries is caught. The backend reported `0.1.0rc4`, and a
  test conversion ran on both the GPU and the software encoder.
- FFmpeg reported build `n8.1.3-27-g8dca1586f4`. Deno reported `2.9.8` and is the pinned file.
- The app's files hold the quick start and its 14 screenshots.

The installer, on a Windows 11 virtual machine restored to a clean state:

- It arrived with the same SHA-256 as above.
- A silent install put the app, its backend, FFmpeg, Deno with its licence, and the licence list
  in place, and the installed Deno ran. Windows' Apps list showed `av-kit 0.1.0-rc.4`, version
  `0.1.0-rc.4`, publisher focalia.ai.
- A silent uninstall removed the app, its Apps entry and the installer's copy in
  `%LOCALAPPDATA%\av-kit-ui-updater`.

On the release commit, 1,657 UI tests, 553 MCP server tests and 3,339 Python tests passed.
The desktop app's end-to-end tests and the live audit of every MCP tool weren't rerun on this
installer.

Not checked on this exact installer: Windows 10, a real video download (with or without Deno), a
real F2 capture, a first voice model download and Transcript (see below).

## Transcript on this build

`YOUTUBE-CAPTIONS-IP-BLOCK`, which blocked caption requests from the test network when
`0.1.0-rc.3` was tested, lifted on 2026-11-17: captions fetch again from that network. The
installed app's Transcript path, from fetching captions to the combined files, hasn't been run end
to end on this build. If YouTube blocks your network, av-kit pauses the job and shows the message.
Try again later or from another network, then choose **Resume**.

## Known problems

None of these are fixed in this release. The names in brackets match
[the project's known issues list](https://github.com/matbanik/av-kit/blob/main/.agent/context/known-issues.md).

**Transcript**

- Adding a whole channel returned an error once, after about 8 minutes of listing its videos. It
  was seen once and the cause isn't known. Adding a channel now reads its list in seconds, but
  whether the error can still happen isn't known. (`TRANSCRIPT-ADD-CHANNEL-422`)

**Text to speech**

- The 13 Japanese and Mandarin voices are listed but can't generate. (`TTS-JA-ZH-G2P-EXTRAS`)
- Spanish, French, Hindi, Italian and Portuguese voices need eSpeak NG installed separately, and
  have never been run end to end with the real program. They may mispronounce words or fail.
  (`TTS-ESPEAK-LIVE-PATH-UNVERIFIED`)

**Capture**

- If the app crashes just after saving a capture an AI assistant asked for, the request isn't
  marked complete. The image is saved, and the request expires on its own after 2 minutes.
  (`CAPTURE-JOURNAL-VOLATILE`)
- In the editor, a text mark's background box can sit 1 or 2 pixels off the saved image's box in
  a few cases. The saved image is right. (`CAPTURE-TEXT-PLATE-METRICS-RESIDUAL`)

## Licences

av-kit's own code is under the [MIT licence](https://github.com/matbanik/av-kit/blob/main/LICENSE).
The components bundled with it keep their own licences:

- `THIRD_PARTY_LICENSES.txt`, attached to this release and installed with the app, holds the
  licence text of what the build actually ships. It's generated from the build.
- `THIRD_PARTY_NOTICES.md`, installed with the app, covers the main components in plain language.
- Deno is under the MIT licence. Its `LICENSE.md` is installed next to it, in `resources\deno`.
- Electron's and Chromium's licences sit in the install folder.

FFmpeg ships as a separate program that av-kit runs, licensed under the GPL, version 3. This is
the same build as in `0.1.0-rc.1` and `0.1.0-rc.3`: `n8.1.3-27-g8dca1586f4` (64-bit Windows, GPL,
BtbN release `autobuild-2026-10-31-12-59`).

That stock build also links libdvdread and libdvdnav, and through them libdvdcss, a library for
reading encrypted DVDs, into `ffmpeg.exe`. av-kit never uses DVD input. The maintainer chose to keep
the stock build rather than build FFmpeg without them, and hasn't had the legal side of shipping
libdvdcss assessed. (`FFMPEG-LIBDVDCSS-BUNDLED`)

FFmpeg's complete corresponding source is attached to this release as
`av-kit-0.1.0-rc.1-ffmpeg-source.tar.xz`. It keeps its `0.1.0-rc.1` name because the FFmpeg build
didn't change, so it's the same file, byte for byte, that `0.1.0-rc.1` and `0.1.0-rc.3` carry. You
don't need it to use av-kit. Its `README.md` says what's inside and names the few things the
build's scripts don't pin.

## Report a problem

Open an issue at <https://github.com/matbanik/av-kit/issues>. These details help:

- the version (`0.1.0-rc.4`) and your Windows version
- what you did, what you expected and what happened
- the exact error text, or a screenshot with anything private hidden

Please don't attach files from `%LOCALAPPDATA%\av-kit`. That folder holds your history and a
private access token.
